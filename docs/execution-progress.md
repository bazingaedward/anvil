# 默认无限执行与工具进度

## 问题

固定 15 分钟任务预算会中断仍在持续编写代码的项目。界面仅显示最后一条活动文字，无法看到已完成工具和当前耗时。

## 方案

- 默认任务预算设为 0（无限），不创建任务计时器。验收检查默认不限制时长（0），自动修复默认不限制轮数（-1）。保留显式传入的有限预算用于测试或主动约束；删除原先 5 次修复、600 秒验收的配置上限。
- 不限制工具调用总次数。手动停止、权限拒绝、实际执行失败仍会结束任务。网络连接探测、协议响应等待和停止后的进程清理超时不属于任务总时限，仍然保留。
- Codex 与 OpenCode 统一输出工具开始/结束事件，展示工具名、简短命令或文件信息、状态及耗时。运行中的工具保持可见，已完成记录可展开；只展示最近记录，历史任务不会被旧的 running 工具误标为仍在执行。
- 模型思考、工具完成、等待用户等状态分别显示。时钟更新不触发新的模型调用；工具概要脱敏后以纯文本渲染，不保存完整工具输出。
- 每轮对话在状态旁展示从提交开始的实时耗时，包含模型、工具及等待用户的墙钟时间。正常结束、失败、取消、达到显式预算时保存独立的结束时间，后续修改记录不能改变耗时。没有完整起止时间的旧记录或崩溃中断记录不推算最终耗时；工具记录不再重复显示对话时钟。

## 验证

验证默认任务可持续运行并手动取消、验收默认无限修复、显式预算仍有效；工具生命周期、重启/取消后状态及前端耗时展示。更新本地运行时并通过 Keygrant 启动开发版。
