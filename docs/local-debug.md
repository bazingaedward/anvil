# 本地调试与 OpenCode 提问

## 问题

OpenCode 2.0 的 question 工具通过 form.created 发出表单。Anvil 只处理 Codex 异步问题，漏接表单事件后，工具一直等待回答，界面停在通用的执行提示。

## 方案

适配 OpenCode question 类型表单为已有提问卡片，保留字段键、选项说明、多选和自定义回答。通过 form.reply 回答原任务，不创建新模型轮次；校验任务归属、运行状态及待回答 ID，拒绝重复和过期提交。Codex 的异步问题保持原有续聊逻辑。等待表单时暂停执行超时计时，取消/退出后历史卡片只读。

在应用数据目录的 diagnostics 中写入有容量限制的事件日志和运行状态快照，通过 npm run debug 快速读取。记录任务 ID、阶段、子进程 PID、事件种类、工具名、最近活动时间、退出码及脱敏错误，不记录提示词、回答、工具参数/结果和凭据。该通道仅本机文件，不开放调试端口。

## 验证

覆盖阻塞问题提交后同一任务继续、重复/失效提交、单选/多选/自定义输入、Codex 异步提问回归；日志脱敏和轮转测试；真实 OpenCode 提问与答复验证。旧版本已挂起的工具不能跨进程恢复内存中的等待句柄，保留历史并明确提示重试。


## 模型请求分段计时（2026-11-16）

问题：会话消息的创建时间不是 HTTP 请求发出的时间，无法仅凭轮次间隔区分内核准备、网络等待和模型服务响应。

方案：只在 OpenCode worker 中观测配置的模型 API 路径，记录每次 POST 请求的开始、响应头、首个非空响应块、结束、失败或取消，以及相对请求开始的毫秒数和 HTTP 状态码。通过现有 JSONL 通道写入本地诊断；不记录 URL、请求头、请求体、响应内容或错误原文，不改变重试/超时策略。响应流按消费者读取，不复制或提前读完整响应。

`model.request` 的 `elapsedMs` 是从该请求开始计时，不是各阶段耗时相加。首个响应块可能是 SSE 元数据或心跳，不能称为首 token；响应头前的等待仍包含网络、排队和服务端处理。结合已有工具开始/结束事件，可区分 HTTP 请求、工具执行和两者之间的间隔；并行工具与模型流可能重叠，不能简单累加。

验证：延迟响应头/响应块的本地流、非模型请求不受影响、失败/取消传递、响应字节保持原样、诊断异常不影响请求、IPC 仅接受已知计时字段。真实服务性能结论需下一次用户任务产生记录后再判断。

## 使用

在项目根目录执行 `npm run debug`，输出最近状态和 30 条事件。macOS 路径为 `~/Library/Application Support/anvil/diagnostics/`，包含 `status.json`、`events.jsonl` 和最多一个轮转文件 `events.jsonl.1`。快照每 5 秒更新心跳，超过 15 秒未更新标记 stale；这是主进程心跳，不等同于模型仍有输出，需同时查看 runtime.lastEventAt。测试或不同配置目录使用 `ANVIL_TEST_USER_DATA` 指定。

记录启动、IPC 失败、任务异常、运行时 PID/退出、问题 ID、状态和渲染进程异常。stderr 只统计字节数，不保存可能含凭据的原始工具输出。日志每个文件约 1MiB 上限，不上传服务器。
