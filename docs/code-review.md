# 本地代码审查工作区

## 入口与布局

最左侧固定图标栏提供 Conversations 和 Code review 入口，中间面板随功能显示对话或仓库列表。顶部 Left panel 按钮统一展开/折叠中间面板，折叠偏好本地保存，图标栏始终可见。对话列表不再展示搜索框。顶部不再显示 Conversation / 仓库 Tab。返回 Conversations 时保留对话及输入草稿；切换仓库保留各自的筛选、视图和选中项。通过原生目录选择器添加仓库，打开审查不改变 Agent 工作目录或对话授权。

默认展示完整宽度的提交图表，包含 Graph、Description、Date、Author、Commit。根据 git log --topo-order 返回的完整父提交关系计算彩色节点和分支连线，包括合并和共同祖先；分支及标签显示为徽标。未加载的父提交连线延伸至当前列表底部。

支持选择本地/远端分支、显示远端历史、搜索提交标题/作者/哈希/引用、刷新以及按需加载。搜索高亮匹配行并淡化其他行，保留拓扑连线；搜索范围是已加载的提交。默认不以 refs/stash 为历史入口，用户可显式开启 Stashes。首批 100 条，最多 1,000 条。

点击提交后，下方展开逐文件补丁导航与只读 Diff，关闭详情恢复完整图表。行尾 ↔ 选择比较起点，再点击另一提交比较两个树。工作区变更单独列出暂存和未暂存文件，使用只读 Monaco Diff。

## 数据与安全边界

IPC 根据主进程已添加目录校验权限，不自动向上扩展到父仓库；独立 Workspace 实例避免干扰编辑器和终端。分支参数必须匹配本地 Git 返回的完整引用名称，比较只接受完整提交哈希。禁用外部 diff 和 textconv，命令受既有 8 MiB 输出上限和 15 秒超时约束，超限明确报错。已有工作区大文件、二进制、符号链接和冲突限制仍有效。

## 远程更新（Fetch）

问题：本地刷新只读取已缓存的远端引用，无法展示刚推送到服务器的提交。

方案：在仓库标题右侧、刷新按钮旁增加云朵向下箭头按钮（Fetch remotes）。点击后对明确添加的仓库执行 `git fetch --all --no-prune --no-recurse-submodules`，成功后重新加载状态和提交图。使用 Git 已配置的远端及凭据；网络操作最长 120 秒，失败显示错误，不自动重试。执行时禁用重复点击。进度和失败反馈使用浮动提示框，不占用页面布局；旋转图标放在固定尺寸、裁剪溢出的容器中，长错误文本单独滚动，避免旋转触发滚动条或布局跳动。Fetch 和历史刷新成功后自动关闭浮层；Dismiss 关闭提示但不取消 Fetch，失败后重新显示可关闭的错误提示。

Fetch 更新远端引用和对象，不执行 pull、merge、rebase、push、stash 或清理远端引用，不修改当前 HEAD、暂存区和工作文件。无远端时给出明确提示。使用本地远端夹具验证新增提交可见、脏工作区保持不变及失败路径；IPC 继续执行仓库访问校验。

## 后续范围

目前提供本地只读代码审查，尚未连接 GitHub PR 列表、评论、检查和合并，除上述 Fetch 外，不执行修改工作区的 Git 操作。历史 Diff 为统一文本补丁，未接入 Monaco 历史双栏 Diff；比较使用两个树，不包含 PR merge-base 语义。后续再接提交、推送、PR 创建和审查讨论，不在当前界面放置无效入口。
