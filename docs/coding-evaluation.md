# Coding 评测基线 v0

这是内部 harness 校准套件，不是公开排行榜，不足以判断 DeepSeek 与 Opus 的整体差距。首版 10 个小型 Node.js 任务覆盖边界修复、跨文件、解析、异步、不可变数据、补测试、仓库入口、多目录和多轮续聊。后续需要加入真实仓库任务、重复运行和预算对照。

## 使用

- `npm run eval:coding -- --list`：列出任务，不访问模型。
- 通过 Keygrant 注入 BYTEPLUS_ARK_API_KEY 和 BYTEPLUS_ARK_RESPONSES_URL 后执行 `npm run eval:coding`。
- `--task=resume` 等参数只运行一个任务。
- `node --test test/eval.test.mjs` 验证每个任务的初始实现失败、参考实现通过，不访问模型。

运行复用桌面 startRuntime → 编译后的 OpenCode worker，不使用独立自研 agent loop。每个任务独立工作目录与会话，单任务总超时 180 秒；续聊任务复用原生 session。首版直接测 runtime，不包含桌面 Agent 的自动验收修复轮次。

## 验收与记录

验收发生在模型执行结束之后，只复制任务声明的实现文件到新目录，再执行仓库维护的断言。agent 修改工作目录的测试或配置不会替换验证器。补测试任务要求保留原实现，并用三个错误实现检验其新增测试能否发现回归。参考答案与验证器不主动放入模型工作目录。

这只是逻辑分离，不是安全隔离：本地 runtime 和验证器执行的代码拥有本机权限，评测自动允许工具请求，仅供本项目可信的小型任务使用。不能声称隐藏测试对恶意 agent 不可见；外来任务应先接入容器/VM（例如 Harbor 的执行环境）。

报告位于 `.anvil/evaluations/<timestamp>/summary.json`，保存模型 ID、协议、Git revision、任务集 hash、runtime 二进制 hash、平台、权限策略、超时、每题通过情况、耗时和工具活动事件数量。实现文件副本与临时工作区保留供排查。密钥、API URL、回答正文不写入报告。

用量与成本目前为 null：底层 worker 尚未转发真实用量，不用字符数冒充 token。工具活动数是 worker 观测事件数，不代表完整工具追踪。运行次数首版为每题一次，不计算置信区间，也不自动重试失败任务。预算只限制时间，不提供硬性费用上限。

## 下一轮怎么改

先人工检查失败文件和报告，将失败归类为上下文遗漏、方案错误、工具问题、提前结束或会话丢失。固定模型、任务、权限和运行环境，每次只改变一个 harness 策略，然后重复运行比较。首版不因失败而自动调整提示词或重新刷分。

Windows / DeepSeek `deepseek-v4-1-flash-261017` / Responses，Runtime 基于 `e081056`，评测代码当时尚未提交。10 个任务每题运行一次，结果 10/10；累计任务耗时 166.1 秒，观测到 70 次工具活动。无自动重跑、无验收反馈修复，token/费用未采集。

补测试任务通过三个变异实现检查；两轮续聊保留 uppercase 约束。没有失败样本可支持有针对性的 harness 改进结论。当前题目规模偏小、难度偏低，下一轮应加入真实仓库、多文件依赖、长上下文和连续修复；不得将本次结果用作与 Opus 的能力对比。
