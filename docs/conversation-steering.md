# 对话转向、排队与紧凑输入框

## 问题

运行中输入框只有停止按钮，用户无法补充指令；空输入框仍占据多行高度。

## 方案

- 空输入框默认单行；文件、目录引用或多行文字使其向上展开。发送或清空文字后按剩余引用恢复高度。保留模型和权限入口。
- 发送成功后清空输入框中的目录引用标签；已发送消息保留目录快照。会话的目录授权继续有效，并可在记忆/上下文入口查看；标签与授权分开管理，不因发送而撤销权限。
- Enter 发送，Shift+Enter 换行，输入法确认不发送。
- 同一对话运行中，默认发送执行 **Steering（转向）**。OpenCode 2.0 使用 session inbox 的 `delivery: "steer"`，本地 Codex 使用 `turn/steer`。不启动第二个并行 agent，不取消正在执行的工具。实际读取时机由内核决定。
- 独立的 **Queueing（排队）** 按钮把消息保存在 Anvil 队列，当前任务正常结束后依次启动，沿用最新 session。排队不意味着模型已收到。
- 转向消息展示在当前回复流中，区分待接收、已交给内核、已接收、失败；排队消息显示等待处理，并允许取消。停止当前任务、失败、关闭应用都会取消尚未执行的排队消息，避免意外继续修改文件。
- 初始化期间可提交转向，等待 runtime 就绪再交付；结束竞争或拒绝不自动重试，以免重复执行。草稿只在内核确认接收后清空；失败使用现有 toast。
- 运行中保持模型与权限不变。引用文件可随补充消息发送；修改目录授权仍沿用现有明确的授权入口。

## 验证

验证同一 session 的转向交付、回执和失败；队列顺序、取消、失败和重启恢复；输入框单行、多行、引用、清空以及 Enter/Shift+Enter/输入法行为。完成类型检查、针对性测试与构建，更新本地应用前确认没有运行中的任务。
