# 文件夹可选的对话

## 问题

对话输入区、IPC 和执行器都要求至少一个授权文件夹，导致问答、代码讨论与方案规划也必须先选择本地项目。文件夹应是可选上下文，而不是发送消息的前提。

## 方案

- 没有文件夹也允许点击发送和使用 Ctrl / ⌘ + Enter，沿用现有会话与消息持久化。
- OpenCode 仍需要 cwd。无文件夹会话使用应用数据目录下按会话隔离的内部工作目录，不借用全局已打开的项目，不把内部目录加入授权文件夹。
- 传给运行时的授权目录列表保持为空，并说明当前没有用户选择的项目；用户可随时通过现有入口添加文件夹。
- 添加文件夹后使用已授权目录，移除最后一个文件夹后回到内部目录；SDK session ID 保持连续。
- Ask / Auto / Full access 的现有权限规则保持不变；内部目录本身不产生自动授权。文件编辑、Git 和项目终端仍需相应项目目录。

## 验证

- 执行器测试覆盖无目录发送、空授权列表、独立 cwd、文件操作仍需确认、添加/移除目录及重启后的 session 延续。
- 桌面测试覆盖全新配置下无目录输入、按钮和快捷键发送、草稿恢复；使用现有运行时/凭据错误验证请求到达执行器。
- 真实模型回复需可用的本机运行时与凭据；后续验证结果见 [macOS 执行内核](macos-agent-runtime.md)。

## 本次结果（2026-11-04）

- 类型检查、生产构建及无文件夹桌面 E2E 均通过。
- 桌面单测 37/37 通过，运行时将 TMPDIR 规范化到真实路径。默认 macOS 临时目录存在 `/var` 与 `/private/var` 别名，原有 acceptance 输出测试直接比较字符串会失败；未修改该无关用例。
- 初次修改使用模拟执行器验证；后续 macOS 内核修复后，真实模型 E2E 已通过先无文件夹对话、再添加文件夹并沿用上下文的步骤。
