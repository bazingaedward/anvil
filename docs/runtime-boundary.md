# Anvil 与 OpenCode 的职责边界

日期：2026-11-08。依据本仓库代码和锁定的 `@opencode/sdk` 2.0.0。

本文同时记录目标分工、已核实的现状和待办；目标能力不能视为已经实现。

## 核心决定

OpenCode 管理一次原生会话内的模型/工具循环与上下文；Anvil 管理用户工作、权限策略、跨会话连续性与产品数据。Anvil 不另建工具循环、模型请求重试或第二套历史压缩器。

```text
Renderer → IPC → Anvil 应用服务
                  ├─ Chat / Group / 账号 / 配置同步
                  ├─ 授权策略 / 验收 / 任务状态
                  ├─ 检查点 / 长期记忆（待实现）
                  └─ runtime.ts：执行、事件、审批回复、取消
                            ↓ JSONL
                     worker.mjs：OpenCode 适配
                            ↓
                     OpenCode SDK / Core
```

## 职责表

| 工作 | OpenCode | Anvil |
| --- | --- | --- |
| 模型与工具循环 | 请求、流式处理、工具续执行、底层重试 | 发起与停止任务、整体期限、状态呈现 |
| 供应商 | 协议适配与调用 | 连接配置、模型能力、密钥引用与注入 |
| 工具 | 原生文件、搜索、命令工具 | 工作目录、授权范围、应用专有工具 |
| 权限 | 产生审批请求、执行回复 | ask/auto/full 策略、审批 UI、拒绝后停止 |
| 原生历史 | 消息、工具调用关联、原生 session 存储 | session ID 与 Chat/任务关联；公开展示记录 |
| 当前上下文 | 消息组织、工具输出处理、压缩 | 有预算的附加材料选择；不重复压缩历史 |
| 任务连续性 | 恢复存在的 session | 目标、约束、验收证据、检查点与恢复入口 |
| 长期记忆 | 读取选定资料或调用记忆工具 | 存储、来源、范围、更新、检索与删除 |
| 仓库规则 | 使用底层规则加载能力 | 核实适用范围和加载入口，不重复注入 |
| Skills/MCP | 底层发现与调用机制 | 产品配置、启停、凭据、授权 |
| 验收 | 根据失败证据继续修复 | 固定验收命令、修复次数与时间预算 |
| Git/PR | 执行获准的 Git 操作、分析代码 | diff/graph/PR 工作流、用户审查 |
| 账号/同步 | 无 Anvil 账号职责 | 身份、设备、配置同步与隔离 |
| 评测 | 提供执行信息 | Harbor 适配、任务集、独立验收与指标 |

权限确认不等于 OS 沙箱。目录提示词不能提供文件系统隔离，Shell 执行尤其需要单独评估。

## 当前代码审计

| 领域 | 证据与现状 | 缺口 |
| --- | --- | --- |
| 单一 SDK 入口 | `runtime/opencode/worker.mjs` 创建 host，调用 sessions.create/get/move/switchModel/prompt、permission.reply、interrupt | 新能力继续经适配层暴露，不能让 Renderer 调用 SDK |
| 通信 | `desktop/main/runtime.ts` 统一聊天和 probe 的进程启动、JSONL 校验、事件分帧、审批回复、取消与终态 | 当前只有单轮运行接口，尚无原生 fork/delete 管理命令 |
| 应用任务 | `desktop/main/agent.ts` 保留授权策略、验收修复、状态发布、Chat 数据操作 | 后续可拆分服务，但不要把应用验收循环误认为重复的工具循环 |
| 原生持久化 | worker 的 database.path 为 runtime state 下 sessions.db；StoredTask 保存 sessionID/runtimeState | 没有独立的 session 生命周期表；目前经历史任务寻找最近 session |
| 重启恢复 | Agent.recover 将遗留 running 标记 cancelled；下一次发送复用 sessionID | 不会自动续跑；没有结构化检查点和副作用核对流程 |
| Fork | ConversationStore.fork 复制选定任务前缀并清除 sessionID；首次发送注入文字 transcript | 不是原生历史 fork；不复制工具状态和附件内容，受文字长度限制 |
| 删除 | 删除前停止当前任务；删除应用 SQLite 记录并记录 tombstone | 尚未删除 OpenCode 原生 session；不能宣称所有历史已物理清除 |
| 压缩 | 底层已有实现（见 harness.md），worker 没有单独配置压缩策略 | Anvil 尚未转发压缩/用量等完整事件；本轮未做真实长上下文验证 |
| 规则/配置 | worker 设置 config.project=false，设置独立 config/XDG 路径 | 不能据此断言 AGENTS.md 是否正确加载；需规则发现路径和多目录集成测试 |
| 记忆 | 产品保存 Chat 和任务文本 | 没有长期记忆、候选提取、检索、失效机制 |
| Skills/MCP | 尚未在本次审计中验证实际启用链路 | 不能把上游支持列表当作 Anvil 已接入能力 |

运行事件 completed 只代表模型执行结束。Anvil 无验收命令时映射为 unverified；只有实际验收通过才标记 completed。

## 数据与上下文约定

1. **原生运行历史以 OpenCode 为准。** 应用消息是用于展示和检索的投影，不能静默拼接替换原生历史。现有文字 fork 是明确受限的兼容行为。
2. **应用数据库以 Anvil 为准。** Chat 标题、分组、账号、权限、验收条件不交给 SDK 管理。
3. **压缩摘要、检查点、长期记忆分别保存。** 压缩摘要用于当前会话；检查点保存目标和进展；长期记忆保留经确认的跨会话知识。
4. **动态事实重新核查。** 分支、工作区 diff、运行中的服务和当前测试结果不能直接沿用旧记忆。
5. **记忆不是授权。** 恢复和检索不能恢复过期授权，也不能将工具输出中的指令升级为用户指令。
6. **Group 默认只组织聊天。** 不自动共享上下文；跨仓库知识明确绑定来源与范围。
7. **不自动重放整个任务。** SDK 负责模型请求重试；应用在进程故障后先检查状态和副作用，避免重复提交、写文件或创建 PR。
8. **单一规则加载入口。** 先验证原生规则发现；确需应用注入时，明确替代范围和优先级，避免双重加载。
9. **凭据不进入业务记录。** 子进程仅注入选中连接的密钥；错误脱敏，记忆和检查点不保存密钥。

## 本轮落地

- 新增应用侧 RuntimeInput/RuntimeEvent/RuntimeResult/RuntimeRun 契约，不暴露 SDK 类型。
- 聊天与连接测试共用传输实现；权限判断仍在应用层，probe 始终拒绝工具请求。
- 完整校验审批资源类型；对未换行输出也设置上限；终态后忽略后续事件。
- 进程结束前等待退出或强制停止，不在错误后自动重放。
- 保持当前 JSONL 协议兼容，不迁移数据库，不改 UI，不引入记忆内容。

## 后续顺序与验收条件

1. **补生命周期管理。** 明确原生 session 的创建/恢复/fork/delete 能力，增加应用侧映射与删除重试状态。验证删除失败可恢复、fork 不共享后续历史，不直接编辑 SDK 数据库。
2. **补规则与上下文证据。** 验证 AGENTS.md 在单目录、多目录和目录切换后的加载；转发真实压缩/用量事件；验证不同模型窗口配置。
3. **任务检查点。** 持久化目标、用户修正、进度、证据、阻塞与下一步。区分模型生成摘要和实际工具证据。验收重启/压缩后不漏约束、不重复副作用。
4. **长期记忆。** 先支持显式保存、来源与范围、修改删除，再增加检索和自动候选。验证过时事实、跨账号/仓库隔离和 Group 不自动共享。
5. **评测与同步。** 用固定任务比较恢复成功率、约束保留率与上下文成本；用户偏好同步和仓库知识同步分别定义，不顺带上传全部聊天。

本轮测试使用可控假 worker 验证传输与应用行为，不代表已经验证真实模型质量或原生压缩行为。


## 2026-11-15：兼容本地 Codex

统一 Runtime 同时承载 OpenCode worker 与本地 Codex worker。Agent 选择执行器并传入权限模式；Runtime 保留 Codex 专用的 Electron Node 模式、CODEX_HOME、系统代理和进程树清理，不向 Codex 注入 API 凭据。提问事件在传输层校验，应用层仍负责去重、持久化与回答续聊；工具活动继续发布给界面。

此次合并不改变原生会话归属：API 会话由 OpenCode 保存，Codex 线程由官方 CLI 保存；跨执行器仍需新建或 fork 聊天。
