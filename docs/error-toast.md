# 操作错误 Toast

## 问题

聊天发送失败时，错误在输入框下面显示为低对比度小字，不易注意，长错误还会挤占布局空间。

## 方案

聊天发送、附件操作等 `agentError` 和主窗口操作错误使用同一个错误 toast：固定右上角，红色边框和错误图标，显示「操作失败」、具体原因与关闭按钮；不移动聊天或输入框。去除 Electron IPC 的重复异常前缀，保留具体原因。toast 不抢焦点，通过 `role=alert` 通知读屏，保留至关闭或下次操作清除，避免长错误尚未读完就消失。

发送失败继续保留草稿。历史任务失败记录、表单校验和保存草稿的持久警告继续保留在对应位置，避免浏览历史时反复弹出旧错误。

## 验证

隔离的渲染测试验证具体错误内容、关闭后可再次显示、固定位置、不抢输入焦点、不移动输入框或清空输入内容。代码检查确认发送失败分支继续保留草稿，输入框下不再渲染 agentError。类型检查和桌面构建通过；不调用真实模型来制造错误。

测试命令：`ANVIL_BROWSER_CHANNEL=chrome npx playwright test test/e2e/error-toast.spec.ts`。
