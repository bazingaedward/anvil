# 随账号恢复的扩展

## 问题

同一位用户会在不同电脑和仓库使用不同的 GitHub 身份。扩展的安装状态应随 Anvil 账号恢复，仓库读取身份应独立于 Copilot 模型身份。用户还需要在发送前知道当前执行器能用哪些工具。

## 第一版

主导航增加「扩展」，集中搜索 MCP、Skill 和插件。内置 PR 审查包提供 GitHub MCP 和 review-pr Skill。浏览器保持已有的设备支持范围。聊天通过 / 选择 Skill，从添加菜单进入扩展。OpenCode 接收启用的 MCP，托管 Codex 继续使用自己的工具配置。

云端复用账号配置的 revision。安装、启用、自定义 Skill 文本及配套文本文件、仓库到 GitHub 登录名的映射随账号同步。默认仅保留已有的浏览器工具。两个设备同时写时保留先提交的一方，旧客户端写其他设置时保留已有扩展。仓库以 GitHub origin 的 owner/repo 识别；本机目录许可由原流程获取。

PR 审查先提供只读工具。连接时核对实际 GitHub 身份，每次读取都限定绑定仓库。可使用已有的 GitHub CLI 登录，或通过 Keygrant 注入对应账号的 GitHub 凭据。模型凭据与仓库身份分别处理。自定义 Skill 经用户选取并确认后上传。云配置不携带本机启动命令、凭据值或目录授权。

## 验收

- 两个独立会话读回相同配置，跨用户隔离、旧客户端写入和 revision 冲突均有测试。
- 扩展页切换、筛选、Skill 输入和项目绑定能从常规入口操作。
- 以不同本地克隆路径解析到相同仓库；账号不匹配时拒绝返回数据。
- 通过 MCP 客户端实际读取已知 PR，并区分工具测试、模型端到端及真实双设备测试。

自定义 Skill 支持本地目录和 GitHub 公开仓库的固定提交目录链接。导入前列出将上传的 UTF-8 文本文件，云端保存该版本快照，其他设备恢复时无需访问原仓库。脚本文件作为参考文本发送。导入大小上限 150 KB、64 个文件，账号扩展配置总计 180 KB。GitHub MCP 第一版的工具为 read_pull_request，返回 PR 元数据、基线和目标提交以及可分页的变更文件。插件第一版提供内置 PR 审查包。

本机 GitHub CLI 模式复用 gh 登录；首次使用 /review-pr 遇到账号不匹配时弹出连接确认，允许切换 gh 的活动账号。已添加的账号可直接切换，新账号交给 gh 的网页设备授权，成功后继续原提交。选择 Keygrant 模式会按登录名引用 ANVIL_GITHUB_<大写登录名>（短横线转为下划线），该凭据需要能读取相应仓库 PR。gh 和 Keygrant 是本机依赖。

OpenCode 2.0 在 MCP 报告 connected 后会合并 100 ms 内的工具变更，再刷新模型的工具列表。适配器在首轮推理前等待连接及此次刷新。运行 `npm run runtime:build && node test/extensions/cold-start.mjs` 可用本机测试模型端点和 GitHub CLI 测试数据验证首次工具发现、权限回复和结果回传。真实 GitHub 读取另行验收。
