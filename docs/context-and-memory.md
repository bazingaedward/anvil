# 本地文件记忆与上下文边界

更新：2026-11-15。

## 使用方式

直接对 Anvil 说“记住……”或“忘掉……”。Agent 使用现有文件工具维护 Markdown，无需逐条填写表单或为每个聊天勾选记忆。回答下方“存为记忆”仍可用于手动精简保存。

聊天右上角菜单 → 记忆：自动记忆开关、查看/编辑/删除、打开记忆文件夹。自动记忆默认开启，开关为当前账号的本机设置。关闭不删除文件，也不会抹掉已经进入原生聊天历史的内容。

## 文件结构与迁移

每个账号的本地 tasks 目录内：

```text
memory/
  settings.json               # 自动记忆开关，由应用管理
  global/                     # 账号全局偏好
    .scope.json               # 范围元数据，由应用管理
    MEMORY.md                 # 简短索引
    <主题>.md
  <目录绝对路径的 SHA-256>/     # 附加目录的专属记忆
    .scope.json
    MEMORY.md
    <主题>.md
```

Markdown 是记忆的唯一内容来源。Agent 创建普通 Markdown 文件即可被界面识别；应用创建的文件可带 HTML 注释元数据，用于标题、类型、来源。文件内容哈希用于编辑冲突检测，修改使用临时文件原子替换。

旧 SQLite memory_notes 在启动时迁移到确定性文件名，全部成功后清空旧表。已迁移的同名文件不覆盖；重新启动不会重新生成已删除记忆。旧 task_handoffs 数据暂保留兼容，但不再显示、注入或要求填写。

记忆本机保存，不上传云端。跨账号隔离。附加目录撤销后，不再为该聊天注入该目录索引或授予对应记忆权限。目录范围按规范化绝对路径匹配，目前不同 checkout/worktree 不自动合并。

## 自动读取和写入

每轮把适用目录的 MEMORY.md 索引加入上下文，每个索引最多 200 行、12000 个字符。详细主题文件不批量注入，模型通过现有 read/write/edit 工具按需读取，创建或修改主题后维护索引。

模型收到的记忆维护约定：保存稳定偏好、纠正和不能直接从代码获取的知识；不存密钥、临时进度和可重新读取的代码信息；当前用户指令优先，记忆不授予执行权限；写入失败不能宣称保存成功。自动记忆依赖模型遵循此约定，不保证每轮都会产生记忆。

OpenCode 的自动授权仅覆盖适用记忆目录的明确 Markdown 文件读取/修改和精确目录访问，不扩展 shell、MCP 或其他目录权限。Codex 自动模式将记忆目录加入可写范围，逐次询问模式仍遵守其只读沙箱与原生审批。

## 与 runtime 的边界

OpenCode / Codex 继续负责原生 session、工具循环、上下文压缩和聊天延续。Anvil 不再增加用户填写的目标、约束、下一步表单，也不把历史模型回答当作已验证事实。

本轮没有实现代码快照回滚、云端记忆同步、向量搜索或额外的总结模型请求。删除记忆只影响后续文件读取，验证遗忘时应新建聊天。

## 验证

- 桌面回归：迁移、外部编辑、删除后不复活、并发修改冲突、账号/目录隔离、开关持久化和权限边界。
- 真实 DeepSeek + OpenCode：自然语言写入 Markdown → 新聊天按需读回 → 自然语言删除，三步通过。
